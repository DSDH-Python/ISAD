第 4 章　系统总体设计与智能体架构

好的设计让系统模块化、易维护；智能体架构亦然。本章把需求落成智能体总体架构，理解插件/工作流/对话流/卡片的职责与选型。

第一部分　课程导学

导语 · 本章定位

设计回答"系统怎么搭"。经典的总体设计追求模块化、高内聚低耦合；在智能体世界里，这套思想一点没过时——人设、技能、记忆就是模块，工作流就是低耦合的编排。本章让你学会画一张智能体总体架构图，并知道每个组件该干什么。

三维学习目标
知识
理解系统总体设计原则；掌握智能体架构组成；区分插件/工作流/对话流/卡片。
能力
能为项目绘制总体架构图；能把需求映射到智能体组件；能评估架构模块化程度。
价值
培养模块化与高内聚低耦合思维；理解"设计决定可维护性"；善用防御性设计降低故障。

理论基石 · 信息系统分析与设计

理论 · 结构化设计（SD）

① 模块独立性：耦合 Coupling 越低越好、内聚 Cohesion 越高越好；② 结构图 SC：表达模块调用关系与数据/控制标记传递；③ 变换/事务分析：由 DFD 映射为程序结构；④ IPO 图：输入—处理—输出描述模块内部逻辑。

理论 · 软件架构风格与模式

分层架构（C/S、B/S、三层）；面向服务（SOA、微服务、事件驱动 EDA）；云原生（容器、Serverless）；智能体架构（感知—决策—行动 + 工具/记忆/规划）。

理论 · 面向对象设计（OOD）

类图（类、属性、操作及关联/聚合/继承）；交互图（时序图）；状态图（生命周期）；设计原则 SOLID（单一职责、开闭、依赖倒置等）。

理论 ↔ 智能体能力 映射
模块化·高内聚低耦合 ↔ 智能体技能=高内聚模块；工作流=低耦合编排
结构图/变换·事务分析 ↔ 工作流编排图（节点+连线）
架构风格（分层/SOA/云原生） ↔ 智能体总体架构：感知—决策—行动+工具/记忆
OOD SOLID ↔ 多智能体职责单一、依赖倒置、易替换
IPO ↔ 感知(输入)—推理(处理)—行动(输出)

第9章《系统设计概述》

第二部分　课程内容

4.1　总体设计原则

四个基石原则：① 模块化（复杂系统拆为单一职责模块）；② 高内聚低耦合（模块内紧密相关、模块间少依赖）；③ 可复用（组件像积木可被多处调用）；④ 易维护（变更局部化，便于调试迭代）。

4.2　智能体架构组成

不同平台的界面和命名各异，但智能体通常由三类职责组成：

  • 人设与回复逻辑：定义角色、技能与回复规则（=需求规格），是智能体"大脑"。
  • 工具与知识接口：按产品能力选用连接器 / API / MCP、工作流、知识库或富媒体组件；并非每个平台都提供全部组件。
  • 记忆区三类：变量（记昵称/进度）/ 数据库（结构化业务数据）/ 记忆库（自动沉淀用户画像）。

可视化编排工具可用节点与连线定义数据流向；代码框架则通过模块、接口和配置实现同类职责。调试时均应关注输入输出、错误处理与运行日志。

4.3　四种扩展能力怎么选

能力本质何时选
插件工具箱（封装外部 API）需实时/专业外部信息
工作流流水线（多步骤可控）步骤固定、结果稳定可控
对话流连续对话（记忆上下文）需多轮、记住历史上下文
卡片信息看板（富媒体）美化输出界面（须依附工作流/插件）

4.4　知识库赋能：防御性设计

参考 KB《软件防御性设计专家提示词》：在系统设计阶段识别故障点并嵌入恢复机制。对智能体，为工作流增加异常/兜底分支（选择器"否则"分支 + 变量聚合节点统一输出）；为提示词增加边界处理（超范围请求明确说明并尝试用通用知识回答）。把组件当作独立模块，便于测试与复用。

4.5 插件详解 & 4.6 编排详解

插件分三类来源：官方（优先用）/ 资源库 / 自定义（须先发布）。添加路径：编排→技能→"+"→搜索→展开工具→添加（如头条搜索、墨迹天气）。入参告诉插件做什么、出参以 JSON 返回，节点间用 {{变量}} 串联。

工作流画布：开始→处理/逻辑节点→结束，节点类型含大模型/插件/代码/知识库/消息，逻辑节点含选择器、循环、批处理。对话流：大模型/意图识别节点读取历史对话、自动保存上下文，适合客服、顾问等需记忆的场景。案例：双语社交文案生成器=插件+大模型串联；AI 健身教练=对话流维持记忆。

第三部分　拓展练习

知识拓展与前沿

拓展 · 智能体三大核心组件

① 推理 Reasoning（规划 + 反思）；② 工具 Tools（经函数调用访问搜索/API/数据库/代码解释器）；③ 记忆 Memory（短期会话上下文 + 长期跨会话个性化）。

前沿 · MCP 重构 Agent 工具生态

MCP（模型上下文协议）为"工具—模型"提供统一标准接口，拓宽应用边界、降低集成成本、提升互操作性。设计建议：工具与权限成对定义，遵循最小权限原则。吴恩达提醒落地仍需关注稳定性与安全。

拓展 · Agentic 架构 vs Agentic 工作流

架构回答"系统由什么构成"（相对稳定骨架：≥1 个可决策 Agent + 工具 + 记忆）；工作流回答"系统如何运转"（计划→分解→工具执行→反思调整，随任务动态变化）。

🧩 案例 · 高内聚低耦合的智能体架构

  • 场景：把‘查政策 / 答疑问 / 约咨询’拆成三个子智能体，由一个调度智能体按意图路由——改一个不影响另外两个，正是高内聚低耦合。
  • 防御性：总体设计阶段就标注‘如果用户问隐私怎么办’：给拒答边界与转人工节点，设计即伦理。
  • 映射：本章‘模块 + 接口’思想，可映射到各平台的主流程/子流程、工具或技能；也可用 MCP、函数调用或自定义代码实现接口。

上机实验 · 设计智能体总体架构

📋 实验任务书

目标：基于需求产出可追溯的智能体总体架构图与失效点分析。

环境：任一可用智能体平台或框架 + 绘图工具（纸笔/在线画图均可）。

步骤：① 画架构图（人设/技能/记忆）；② 标注需求对应；③ 用 KB 防御性设计提示词做失效点分析（3 点 + 恢复机制）；④ 在选用工具中搭建可演示的骨架或接口原型。

交付物：总体架构图 + 失效点分析清单 + 原型界面或关键配置截图。

评分点：架构完整(30%) · 需求可追溯(25%) · 防御性分析(30%) · 骨架搭建(15%)。

🛠 分步操作 · 为项目设计智能体总体架构

动手 · 分步操作
  1. 基于第 3 章需求，绘制智能体架构图：人设/回复逻辑 + 技能（插件/工作流/知识库）+ 记忆。
  2. 标注每个组件对应的需求条目，体现"需求→架构"可追溯。
  3. 用 KB《软件防御性设计专家提示词》做一次失效点分析：列 3 个故障点与恢复机制。
  4. 在所选工具中按架构搭建骨架：创建智能体、配置对应工具/技能占位，或画出待实现接口。
📝 架构图自检清单

□ 人设是否覆盖核心需求？
□ 每个技能是否单一职责（高内聚）？
□ 组件间依赖是否最少（低耦合）？
□ 是否都有异常/兜底分支（防御性）？
□ 记忆/知识是否分工清晰（动态 vs 静态）？

拓展案例 · CubeMAP 智能体互联网架构

案例 B7-02 CubeMAP 智能体互联网体系架构创新与实践
申报单位：中国联合网络通信有限公司研究院

本案例“CubeMAP 智能体互联网体系架构创新与实践”由中国联通研究院依托CubeMAP 智能体互联网平台提出并实践，聚焦解决人与智能体交互的门槛壁垒以及多智能体跨域协同的技术难点。针对当前智能体交互严重依赖即时通信应用、对老年及视障群体不友好等问题，案例首创“电话号码即智能体接入点”方案，打通传统电信网与智能体互联网，用户通过普通电话拨打专属号码即可与智能体语音互联，实现了通信入口的极大简化与泛在化。同时，为应对多智能体跨域协作中协议异构、互发现难等挑战，案例构建了基于服务层的跨域协同体系，通过智能体注册发现、多协议适配及动态组网等能力，实现了不同技术栈智能体间的协同调度。

看点：CubeMAP 解决的是两个层面的“连接”：人如何低门槛地连到智能体（电话号码即接入点），智能体之间如何跨域协同（注册发现 + 多协议适配 + 动态组网）。这两条正是体系结构设计中最难的部分。
