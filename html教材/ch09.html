第15章《系统实施》

第二部分　课程内容

9.1　实施与发布渠道

发布不是单一按钮，而是选择部署与分发方式：桌面任务助手（如 WorkBuddy）、模型 API + 自建应用（如豆包 / DeepSeek）、开源框架（如 Qwen-Agent），或低代码平台的 Web / 小程序与平台内发布渠道。上线前应核实各产品当前支持的渠道、审核规则和企业部署条件；发布管理还需包含版本记录、运行监控、权限复核、回滚与下线流程。

9.2　智能体测试策略

  • 功能测试：覆盖各分支、插件路径、工作流节点；用"调试详情"调用树看路径，火焰图看耗时。
  • 边界测试：异常输入、超长文本、缺失参数、敏感词；验证兜底分支（选择器"否则"）与友好提示。
  • 一致性测试：同一问题多次回答是否稳定、是否符合人设。
  • 幻觉与合规：核查知识库回答是否准确引用；缺失内容应明确说明而非编造。
  • 回归测试：变更后重新验证原有功能，保留测试用例集随版本回归。

9.3　运行维护与数据生命周期

数据隔离：测试与线上数据分离、不同渠道隔离；运行监控：发布管理看活跃/对话分布/满意度；热更新：知识库/提示词修改即时生效无须重发；项目复盘：记录故障点与恢复机制，沉淀防御性设计资产与可回退版本。

9.4　综合项目（Capstone）与项目管理

  1. 选题立项：沿用前 8 章成果，明确范围与边界，避免蔓延。
  2. 敏捷迭代：小步快跑、分模块交付（规划→需求→架构→知识→工作流→产品化）。
  3. 测试报告：功能/边界/一致性/合规全覆盖，含用例、预期与实际、缺陷与修复。
  4. 答辩复盘：讲清设计决策与价值、不足与改进；同伴互评+教师点评。

9.5.2　信息系统审计基础（CISA 视角）

信息系统审计师（CISA，ISACA 认证）从"独立验证"角度审视 IT 系统。CISA 五大领域：

  • D1 信息系统审计流程：审计章程、风险导向、证据获取与报告。
  • D2 IT 治理与管理：战略对齐、价值交付、COBIT 框架。
  • D3 信息系统的购置、开发与实施：需求 / 设计 / 开发阶段的设计评审与审计——呼应第3、4章。
  • D4 信息系统的运营与业务恢复能力：运维、连续性、灾备——呼应 9.3 运行维护。
  • D5 保护信息资产：安全框架、数据分级、隐私保护——呼应第5、6章的数据与记忆治理。

常用框架：COBIT（IT 治理）、ISO/IEC 27001（信息安全管理体系）、网络安全等级保护。测试（9.2）本质上就是"运营与合规核查"的工程师视角雏形。

9.5.3　信息系统监理（三控两管一协调）

信息化工程常引入第三方监理把关质量与进度。监理核心职责可记为"三控两管一协调"：

  • 三控：质量控制、进度控制、投资（成本）控制；
  • 两管：合同管理、信息管理；
  • 一协调：组织协调（建设方、承建方、监理方等多方）。

9.5.4　职业资格与职业发展（给你指条路）

  • 软考高级·信息系统项目管理师（高项）：以考代评，可用于评职称、落户、招投标加分；科目＝综合知识 ＋ 案例分析 ＋ 论文。
  • CISA：IT 审计国际认证，适合信息安全、审计、合规方向。
  • 信息系统监理师（软考中级）：监理方向，与"三控两管一协调"对应。

建议路线：大二打牢 ISAD ＋ 智能体基础 → 大三考软考中 / 高级 → 按兴趣选 CISA / 监理深化。本书的方法论，正是这些认证的知识底座。

知识拓展与前沿

拓展 · 智能体评测方法论

为何难评：输出概率性、路径多样、多步工具调用。维度：任务成功率、步骤效率、工具调用正确性、成本与时延。方法：可复现任务集 + 端到端评估 + 轨迹分析；LLM-as-Judge 与人工抽检结合。评测应贯穿全周期：单元→集成→端到端。

前沿 · 智能体安全与防护

自主性↑→可靠性↓，需主动护栏；权限最小化并持续审查 Agent 权限；高风险/敏感决策保留人工兜底；面向"智能威胁时代"重建网络抵抗力（安全左移、设计即安全）。

案例 · 企业级智能体快速落地路径

选场景（高频、规则清晰、价值可量化）→ 搭原型（低代码+知识库+工作流）→ 设护栏（权限/审计/复核/重试）→ 上生产（灰度→监控→数据回流迭代）。

本章学习方法 · PDCA 循环（Plan-Do-Check-Act）

核心理念：用「计划-执行-检查-处理」持续迭代，每次上线都复盘改进，项目质量螺旋上升。

四步/要点：① Plan 计划定目标、范围与实施方案　② Do 执行小步实施，快速出可用版本　③ Check 检查测试与度量，收集真实数据　④ Act 处理复盘问题并标准化、再迭代

与录屏结合：录屏讲解你综合项目时，用 PDCA 四步展示「上线前测试清单如何闭环保障质量」。

拓展案例 · 江小智一站式数智赋能

案例 B8-02 江小智一站式数智赋能创新实践
申报单位：中国移动通信集团江西有限公司

为落实央企数智化转型部署及集团“AI+”行动计划，江西移动针对AI 能力分散、业务流程繁琐、技术与业务融合不深等核心痛点，打造“江小智”一站式数智赋能体系，有效推动AI 技术与核心业务深度融合。构建统一数智赋能能力底座，实现从“数、算、模、台”的端到端支撑，让数据高效流转、模型便捷调用、算力统一调度、应用快速上线，推动智能应用规模化落地。打造“一站式”AI 服务统一门户，降低应用门槛，实现AI 能力集中化供给与高效调用，支撑落地60 余项高价值AI 应用，核心业务效率显著提升。

看点：江小智走的是“统一底座—统一门户—标杆场景—规模推广”的路线，60 余项应用、2 万+ 用户、累计调用 2000 万次。这是一份可以直接当作项目管理范例的落地样本。

延伸思考题

  1. 江小智以“整合能力底座 → 打造统一门户 → 深耕标杆场景 → 规模推广”的路径落地。请把它改写为一份项目里程碑计划，须包含阶段、交付物与验收标准三列。
  2. 案例同时给出“AI 能力累计调用 2000 万次”与“网格智能体赋能一线提效 35%”两类指标。请区分哪类是过程指标、哪类是结果指标，并说明项目验收应以何者为主、为什么。
  3. “大模型挂载小模型、小模型驱动大模型”的 RAG 开放平台需要长期运营。请列出三项运维期关键活动，并指明各自的责任人角色。
