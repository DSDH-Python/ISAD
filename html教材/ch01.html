理论基石 · 信息系统分析与设计

理论 · 信息系统的定义与构成

经典定义：信息系统是由人、机（计算机及网络）、数据、流程等要素组成，对信息进行采集、处理、存储、传输与利用，以支持组织决策与运作的人—机—数据系统。 其一般模型为"输入—处理—输出 + 反馈"。这与 1.2 节的智能体四能力形成清晰对应。

理论 · 信息系统的多维分类

按层级与目标可分为：事务处理系统（TPS）、管理信息系统（MIS）、决策支持系统（DSS）、专家系统（ES）等； 按技术架构可分为集中式、客户机/服务器、浏览器/服务器（B/S）、以及今日的智能体架构。 智能体架构可视为 B/S 架构在"交互智能"上的进化形态。

理论 ↔ 智能体能力 映射
感知 ↔ 输入/数据采集（表单、接口、爬虫）
认知推理 ↔ 处理/计算（业务规则、算法）
行动 ↔ 输出/执行（报表、消息、写库）
记忆 ↔ 数据存储/知识管理（数据库、知识库）
延伸 · 智能体理论基础（节选自权威指南 1.2）

经典教材《人工智能：一种现代方法》(Russell & Norvig, 1995) 把 AI 的目标定义为"构建理性智能体"：对每一个可能的感知序列，选择使预期效用最大的行动。在 LLM 时代，系统提示词"你是一个……助手"即定义了当前任务的效用边界——指令即目标；这解释了为什么"提示词写不清，智能体行为就混乱"。

智能体与环境的交互在数学上建模为 POMDP（部分可观测马尔可夫决策过程）：真实世界中它只能看到局部观测，需依赖"信念状态"决策；上下文窗口本质就是信念状态的文本化表示，记忆 / RAG 则是为了在部分可观测的世界里更好地估计这一状态。

第二部分　课程内容

1.1　认识智能体：从"软件代理"到 LLM 驱动

"智能体"并非新词。早在上世纪 90 年代，软件代理 研究就提出：让程序像"代理人"一样替用户干活。但彼时的智能体多为规则驱动，能力受限。 真正让智能体"破圈"的，是大语言模型（LLM） 的成熟——它赋予了智能体"理解语言、推理规划、生成内容"的通用大脑。

我们可以这样定义：智能体是一种以 LLM 为认知核心，能感知输入、自主决策、调用工具并采取行动，以完成开放任务的软件系统。 它和传统信息系统的根本区别在于"主动性"——传统系统等指令、按流程走；智能体能自己拆解目标、选择路径、在反馈中修正。

💡 一句话记忆：传统信息系统是"你告诉我怎么做"，智能体是"你告诉我目标，我来想办法"。

1.2　智能体的四大核心能力

无论平台如何包装，一个能干的智能体通常具备四种能力，恰好对应信息系统的基本职能：

核心能力含义对应信息系统职能
感知（Perceive）接收用户输入、读取文件/网页/数据库输入 / 数据采集
认知与推理（Reason）理解意图、规划步骤、做判断处理 / 计算
行动（Act）调用插件、写文件、发消息、返回结果输出 / 执行
记忆（Remember）保存对话历史与长期经验数据存储 / 知识管理
延伸 · 从"单体多技能"到工程化（节选自权威指南 1.1.6）

智能体并非一蹴而就。从早期自定义 API 到今天的标准化工具连接，核心演进可总结为四个维度：

维度痛点解决方案关键技术词
集成烟囱式开发，扩展难工业级协议实践，趋向即插即用Tool-aware
智商走一步看一步，易出错三思而后行，分层思考Reasoning LLM, Reflection
安全容易被"忽悠"，防不住权限隔离，硬性审计Policy as Code, Zero Trust
效率臃肿、思维混乱小而美，协同作战MAS, State-sharing

更进一步，Agent 时代可统一到一个三维思考框架——Goal（目标工程）· Context（上下文工程）· Constraints（约束）：能力不只取决于模型智力，更取决于这三者的设计完整性与平衡；进入生产环节时，约束层的成熟度往往成为瓶颈。

对信息资源管理专业的同学而言，这正说明：智能体没有脱离信息系统范畴，而是把"采集—处理—存储—输出"这个经典闭环，用更自然的人机交互重新封装了一遍。我们过去学的数据组织、知识分类，恰是"记忆"与"知识"能力的理论基础。

1.3　"感知—决策—行动"循环

智能体的运行是一个持续闭环（如图）。它先感知环境与用户诉求，再决策（LLM 规划"下一步做什么"）， 然后行动（调用工具或修改状态），行动结果又成为新的感知输入——如此循环，直到目标达成。

感知 → 决策 → 行动 →（反馈）→ 再感知 → …

这个结构源自控制论的反馈环。 与瀑布式信息系统"需求→设计→实现→交付"的单向推进不同，智能体是自适应闭环：它允许在执行中根据环境变化调整计划，这也是它更"像人"的原因。

延伸 · 智能体认知层级 L1–L5（教学分层模型）

智能体的能力并非"有或无"的二元对立，而是连续光谱。权威指南给出五级教学模型，按"单体系统通常承担的能力复杂度"组织：

层级定位核心特征 (Key Logic)人类对标常见实现要素
L1助理Talk（对话）图书馆员RAG, 提示词工程
L2工人Do（执行）实习生ReAct, Tool Use, CoT
L3自主Learn（学习）工程师向量数据库(Memory), Reflexion
L4进化Evolve（进化）科学家/极客Self-Coding, APE
L5群体Connect（连接）公司/社会多智能体框架, SOP
💡 设计启示：不要盲目追求高层级。L1 足够好（知识库问答不必上 L2，以免增加幻觉风险）；L2 是大多数企业级应用的基石；L3 慎用于高可靠场景（如金融交易）；L4/L5 目前仍主要处于研究原型阶段，落地需审慎评估。

1.4　扣子（Coze）低代码开发环境

扣子（Coze） 是本课程的统一实践平台。它的核心优势是低代码：你不需要写 Python，只要在可视化界面里"填人设、加知识、接插件、拖工作流"，就能产出一个可用智能体。

其工作空间主要包含：① Bot 编排页（配置人设与提示词、知识、插件）；② 工作流画布（用节点拖拽表达业务逻辑）； ③ 预览与调试面板；④ 发布渠道（豆包、飞书、API 等）。对零编程基础的信息资源管理学生，这套界面把"系统设计"直观地变成了"搭积木"。

1.5　智能体基本开发流程

无论复杂与否，开发一个智能体都遵循一条主线：

  1. 定义目标：这个智能体替谁、解决什么问题？（对应系统规划）
  2. 设计人设与提示词：用自然语言写清它的角色、语气、能力边界。（对应需求/设计）
  3. 添加知识与插件：挂载专属资料库、接入外部工具。（对应系统设计/集成）
  4. 编排工作流：把多步逻辑用节点串起来。（对应详细设计）
  5. 测试与调优：用真实问题验证效果，迭代提示词。（对应系统测试）
  6. 发布：部署到对话平台或业务系统。（对应实施）

注意：这条流程与信息系统生命周期（SDLC）高度同构——智能体开发不是"另起炉灶"，而是用新工具重走一遍 ISAD。这正是本课程改革的设计初衷。

延伸 · 智能体工作流四大模式（节选自权威指南 1.5）

智能体工作流强调"迭代、自主、目标导向"。与传统单次提示词相比，差异如下表：

维度传统提示词智能体工作流
交互模式单次请求-响应多轮迭代执行
控制权用户完全控制AI 自主决策
执行时间毫秒〜秒级秒级〜分钟级
能力边界模型内在知识工具扩展后的能力
结果质量依赖提示词质量可通过迭代改进

典型模式：① 规划-执行（先定计划再逐步执行，适合结构化任务）② ReAct（推理+行动交替，适合探索性任务）③ 反思-改进（执行后自我评估，适合质量把控）④ 多智能体协作（角色分工协同，适合复杂项目）。其共同底座是：状态管理、工具接入、终止条件、可观测性与人机协作护栏。

1.6　主流智能体开发平台选型（信息资源管理视角）

除 Coze 外，业界还有 Dify、文心智能体、通义星尘、豆包、以及面向开发者的 LangChain 等。选型时建议从三个角度判断：

平台零代码友好度知识库能力合规与本地化
扣子 Coze高强（多格式）国内合规、易发布
Dify中（可私有部署）强支持本地化部署
文心 / 通义 / 豆包高中国内合规

第三部分　拓展练习

知识拓展与行业前沿

拓展 · 智能体的严格定义与四要素

学界常从四个属性刻画智能体：自主性（无需持续干预）、反应性（感知并响应环境）、 社会性（能与其他智能体/人协作）、主动性（主动发起达成目标的行为）。这比 1.2 的"能力"视角更偏"行为属性"。

前沿 · 从传统智能体到 LLM 驱动新范式

传统智能体多为"符号规则 + 规划器"；LLM 驱动范式把"策略"交给了大模型—— 提示词即策略（prompt as policy）。这使得非程序员也能通过自然语言"编程"，也带来了可解释性、稳定性等新挑战。

拓展 · 智能体的三种分类维度

① 按能力：简单响应式 / 任务型 / 多智能体协作型；② 按自主性：辅助型 / 自主型； ③ 按场景：客服、研发、数据分析、知识管理。本课程主线落在知识管理型任务智能体。

🗂️ 案例 · 网络语言智能系统（课程贯穿项目）

  • 🎯 场景：把 2004–2026 年的互联网流行语与心灵鸡汤，建成一个"年度热词档案馆"智能体。用户说"讲讲 2021 年"，它从知识库检索该年热词，输出「词 + 含义 + 来源场景 + 情感基调」。
  • 🤖 四要素映射：角色=热词讲解员；工具=RAG 检索；行动=汇总成卡片；完成条件=覆盖该年 Top 热词。这正是本章"智能体=嵌入业务流的能力单元"的第一个可触摸例子。
  • 🧩 对应能力：本章"信息系统的智能体化"主线——你不必先写代码，而是先想清楚"目标是什么、需要哪些工具、何时算完成"。
💡 算法冷知识：把全部热词按年份聚合，画一条"内卷→躺平→松弛感"的情感时间序列，就是"数据→信息→知识"的 DIKW 可视化；用 Coze 上传《流行语编年表》为知识库即可零代码跑起来。

本章学习方法 · 费曼学习法（Feynman Technique）

核心理念：真懂的标志是"能讲给外行听明白"。本章把费曼法翻转应用——不是你读完了做测验，而是你录屏讲解自己的实验，讲不清的地方就是你没真懂的地方。

四步闭环：① 选概念（挑一个你以为懂了的术语，如"感知—决策—行动循环"）② 讲出来（假装教外行，大白话+画图）③ 找漏洞（卡壳处即盲区，回去补）④ 简化（用一句生活类比收尾）。每章的"实验录屏"都是一次费曼演练。

上机实验 · 创建你的第一个智能体

📋 实验任务书

目标：在 Coze 中独立创建一个"图书推荐助手"（或旅行助手），跑通"目标→人设→知识→插件→发布"全流程。

环境：扣子 Coze 工作空间（自备账号）。

步骤：① 新建 Bot 并撰写人设；② 上传一份书目/攻略资料作知识库；③ 绑定 1 个插件；④ 用 3 个真实问题调试；⑤ 发布到豆包并截图。

交付物：Bot 链接 + 调试对话截图（≥3 组）+ 100 字反思（提示词如何影响回答质量）。

评分点：人设清晰(20%) · 知识库相关(20%) · 插件调用正确(20%) · 回答质量(25%) · 反思深度(15%)。

🛠 分步操作 · 5 分钟第一个智能体（旅行助手）

动手 · 分步操作
  1. 登录 Coze 工作空间，点击"新建 Bot"。
  2. 写人设与开场白：例如"你是一名资深旅行规划师，语气亲切，擅长根据预算与天数定制行程"。
  3. 加知识：上传一份本地"城市攻略.docx"作为知识库，让智能体基于真实资料回答。
  4. 绑插件：添加"天气查询""网页搜索"插件，赋予实时信息能力。
  5. 预览调试：在右侧对话框问"三天两夜、预算 2000，去成都怎么玩？"观察回答质量。
  6. 发布：选择"豆包"等渠道，得到可分享的链接。
📝 提示词模板（可直接套用）

角色：你是一名[领域]助手。
能力：能完成[任务A]、[任务B]，必要时调用[插件]。
约束：仅基于[知识库]回答；不确定的事主动说明；语气[风格]。
开场白：[一句引导用户提问的话]。

🔬 扩展实验（选做 2–3 项，巩固费曼讲解能力）

扩展实验 1 · 插件能力对比感知 / 行动

任务：为"图书推荐助手"分别绑定「网页搜索」与「天气查询」两个插件，针对同一问题（如"适合雨天读的书"）观察回答差异。

交付：一张对比表（插件 / 是否用到实时信息 / 回答质量），并用费曼法录屏讲清"插件如何扩展智能体的行动能力"。

扩展实验 2 · 人设对比实验认知 / 提示词

任务：复制同一 Bot，仅修改"人设语气"（严肃学者 vs 亲切朋友），用同一组 3 个问题测试，记录回答风格差异。

交付：截图对比 + 一句费曼式总结："提示词如何像开关一样改变智能体的行为策略"。

扩展实验 3 · 平台选型调研决策 / 选型

任务：注册试用 Coze 与 Dify（或文心/通义）的免费版，各建一个最小 Bot，从"零代码友好度 / 知识库能力 / 合规"三维度打分。

交付：一份选型评分表，并录屏讲解"为什么信息资源管理者更看重知识库与合规"。

本章小结

核心要点回顾

  • 智能体 = LLM 为脑 + 感知/认知/行动/记忆四能力的自适应系统。
  • 其运行是"感知—决策—行动"反馈闭环，区别于瀑布式单向开发。
  • 四能力 ↔ 信息系统"采集—处理—输出—存储"职能同构；开发流程 ↔ SDLC 同构。
  • Coze 等低代码平台让零基础者也能实践 ISAD 全流程；选型看重知识库与合规。
  • 科技自立自强：做平台的使用者，更做技术主权与数据主权的理解者。

拓展案例 · 天工超级智能体

案例 B2-06 天工超级智能体（Skywork Super Agents）
申报单位：昆仑万维科技股份有限公司

天工超级智能体（Skywork Super Agents）是昆仑万维于2025 年5 月22 日全球发布的“AI Office 智能体”。它基于 AI Agent 架构与 Deep Research 技术，旨在颠覆传统 Office 工作流，首发即在 GAIA 榜单以 82.42 分超越 OpenAI 与 Manus，位列全球第一。平台采用“5+1”架构：5 个专家智能体分别专注于文档、PPT、表格、网页、播客的一站式生成，1 个通用智能体接入数十个 MCP 工具，处理图片、音乐、视频等多模态创意任务。

看点：天工把“先问清楚再动手”做成了产品机制——澄清卡片，并把所有产出都挂上可验证来源。对照本章 1.5 的智能体开发流程看，它等于把需求澄清与结果溯源两步前置并固化。

延伸思考题

  1. 天工的“澄清卡片”在任务启动前主动追问目标、背景与限制条件，并生成待办清单供二次确认。对照本章“智能体基本开发流程”，这套机制相当于把哪一步前置了？如果把它移植到 Coze 的人设与回复逻辑中，你会怎么写这段提示词？
  2. 天工为文档、PPT、表格三类产出都提供了来源溯源。请以信息资源管理的专业视角说明：为什么“可追溯”是信息系统可信性的必要条件？缺失溯源会带来哪些具体风险？
  3. “5+1”架构中，通用智能体接入了数十个 MCP 工具。若让你为一个“校园图书馆咨询智能体”规划工具集，你会选哪 3 个？说明选择依据与调用顺序。
