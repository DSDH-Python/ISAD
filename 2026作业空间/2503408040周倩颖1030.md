## 1. 微信小程序修改用户名或密码的事件流

**场景选择**：某校园跑腿小程序（或常见的电商/外卖小程序）修改密码操作

**基本事件流（正常流程）**：
1. 用户进入小程序，点击“我的”页面。
2. 用户点击“设置” -> “账号与安全” -> 选择“修改密码”或“修改用户名”。
3. 系统弹出身份验证页面，要求用户输入原密码（或发送短信验证码进行验证）。
4. 用户输入原密码并点击“确认”。
5. 系统验证原密码正确，跳转至“设置新密码”页面。
6. 用户输入新密码及确认新密码，点击“提交”。
7. 系统检查新密码格式（如：长度8-16位，包含字母和数字），并确认两次输入一致。
8. 系统将新密码加密后提交至服务器更新。
9. 服务器返回更新成功提示。
10. 系统提示“修改成功”，并强制用户退出登录，需使用新密码重新登录。

**备选事件流（异常流程）**：
*   **4a. 原密码错误**：系统提示“原密码不正确，请重新输入”，返回步骤3。
*   **7a. 新密码格式不符**：系统提示“密码格式需包含字母和数字”，停留在当前页面。
*   **7b. 两次密码不一致**：系统提示“两次输入的密码不一致”，停留在当前页面。
*   **8a. 网络异常**：服务器无响应，系统提示“网络异常，请稍后重试”。

## 2. 图书馆管理系统 UML 图

*(注：以下图表均使用 Mermaid 语法生成，在支持 Mermaid 的 Markdown 阅读器中可直接显示为图形)*

### 2.1 Sequence diagram (顺序图 - 以借书为例)
```mermaid
sequenceDiagram
    actor User as 读者
    participant UI as 系统界面
    participant System as 借阅系统
    participant DB as 数据库

    User->>UI: 请求借阅图书
    UI->>System: 提交借阅请求(读者ID, 图书ID)
    System->>DB: 查询图书状态
    DB-->>System: 返回图书状态(在馆)
    System->>DB: 查询读者借阅额度
    DB-->>System: 返回额度正常
    System->>DB: 更新图书状态(已借出)
    System->>DB: 新增借阅记录
    DB-->>System: 更新成功
    System-->>UI: 借阅成功通知
```

### 2.5 Activity diagram (活动图 - 以借书流程为例)

```mermaid
flowchart TD
    Start((开始)) --> Input[读者提交借书请求]
    Input --> CheckStatus{图书是否在馆?}
    CheckStatus -- 否 --> Fail1[提示图书已被借出]
    Fail1 --> End((结束))
    CheckStatus -- 是 --> CheckLimit{读者额度是否已满?}
    CheckLimit -- 是 --> Fail2[提示借阅额度已满]
    Fail2 --> End
    CheckLimit -- 否 --> Update[更新图书状态与借阅记录]
    Update --> Success[提示借阅成功]
    Success --> End
```
